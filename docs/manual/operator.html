1. 全体の仕組み

画面は全社共通のものを1つだけ公開し、URL に付いた会社コードで、どの会社のスプレッドシートにつなぐかを切り替えます。

2. ひな形を作る（最初に1回）

  1. ポータル用アカウントで新しいスプレッドシートを作り、名前を「【ひな形】内定者ポータル」にします。
  2. 「拡張機能」→「Apps Script」を開き、左の歯車「プロジェクトの設定」→ タイムゾーンを「(GMT+09:00) 日本標準時 - 東京」にします。
  3. 最初からある コード.gs を削除し、「＋」→「スクリプト」で次の5つを作ります。中身は GitHub の gas/ フォルダから貼ります：Config・Common・Setup・Admin・Api
  4. 保存してスプレッドシートを再読み込みし、メニュー「内定者ポータル」→「初期セットアップ」を押します。
  5. 権限の確認が出たら、自分のアカウントを選び、「詳細」→「（安全ではないページ）に移動」→「許可」の順に進みます。その後、もう一度「初期セットアップ」を押します。
メモひな形はデプロイしません。内定者の登録や URL の発行もしません。サンプルデータは、お客様への記入例として残しておきます。

3. 新しい会社を追加する

  1. ひな形を開き、「ファイル」→「コピーを作成」を押します。名前は「【株式会社〇〇】内定者ポータル 2027」のようにします。Apps Script も一緒にコピーされます。
  2. コピーした方を開き、「拡張機能」→「Apps Script」→ プロジェクトの設定でタイムゾーンが東京になっていることを確認します。
  3. 「デプロイ」→「新しいデプロイ」→ 歯車から「ウェブアプリ」を選び、次のように設定して「デプロイ」を押します。権限の確認が出たら許可します。
    説明v1
    次のユーザーとして実行自分
    アクセスできるユーザー全員
  4. 表示されたウェブアプリの URL（https://script.google.com/macros/s/…/exec）をコピーします。
  5. 会社コードを決めて、対応表に登録します（次の章）。
  6. スプレッドシートの「設定」シートで、「会社コード」に決めたコードを入れます。「画面URL」が https://naitei-portal.github.io/portal/ になっていることも確認します。
  7. 会社名・ポータル名・テーマ色など、わかっている項目を入れます。
  8. 動作を確認します。「内定者」シートに自分をテスト用に登録し、URL・パスワードを発行して、スマホで開けるか確かめます。確認が終わったら、その行の「利用」のチェックを外し、「状態」を「辞退」にします（行は削除しません）。

4. 会社コードを登録する

会社コードは URL に入り、対応表は公開されます。社名がわかる文字列は使わず、英小文字と数字のランダムな8文字にします（例：k7f3x9qa）。

  1. ポータル用アカウントで GitHub にログインし、github.com/naitei-portal/portal を開きます。
  2. docs → clients.js を開き、右上の鉛筆マーク（Edit this file）を押します。
  3. window.PORTAL_CLIENTS = { の下に、次の形で1行追加します。最後のカンマを忘れないでください。 
      k7f3x9qa: 'https://script.google.com/macros/s/…/exec',
    社名をコメントで書くと公開されてしまうので、どのコードがどの会社かは社内の管理表で管理します。
  4. 「Commit changes…」→ そのまま「Commit changes」を押します。1〜2分で反映されます。
メモこの作業は Claude Code に「会社コードを作って登録して」と依頼しても行えます。その場合は、ウェブアプリの URL を伝えてください。

5. お客様に渡す

  1. スプレッドシート右上の「共有」から、お客様の採用ご担当者を編集者として追加します。
  2. 運用ガイドの URL をお送りします：https://naitei-portal.github.io/portal/manual/customer.html
  3. 初回は一緒に画面を見ながら、内定者の登録と URL の発行を1人分行うとスムーズです。
注意スプレッドシートは「リンクを知っている全員」で共有しないでください。内定者の名前や記録が誰でも見られる状態になります。共有は、必ず個人のアカウントを指定して行います。

6. お客様のアカウントで作る場合

データをお客様の管理下に置きたい場合は、お客様の Google アカウントで構築します。

  1. お客様が Google Workspace を使っている場合は、組織外との共有が許可されているかを先に確認します。許可されていないと、ウェブアプリの「アクセスできるユーザー」で「全員」を選べません（管理コンソール →「アプリ」→「Google Workspace」→「ドライブとドキュメント」→「共有設定」）。
  2. ひな形をお客様のアカウントに閲覧者として共有し、お客様側で「ファイル」→「コピーを作成」してもらいます。
  3. 以降は「3. 新しい会社を追加する」の手順 2 からと同じです。デプロイは、お客様のアカウントで行います。
  4. ウェブアプリの URL を受け取り、会社コードを登録します。

プログラムの更新も、お客様のアカウントでの作業になります。更新が発生したときは、手順をお送りするか、画面共有で一緒に行います。

7. プログラムを更新する

スプレッドシートの内容（予定やお知らせなど）の変更は、自動で反映されます。この章は、プログラム自体を直したときの作業です。

画面（docs/）を直したとき

GitHub に反映すれば、全社の画面が1〜2分で更新されます。各社のスプレッドシートでの作業はありません。

GAS（gas/）を直したとき

各社のスプレッドシートはそれぞれ別のコードを持っているので、会社ごとに更新します。

  1. そのスプレッドシートの Apps Script を開き、変更のあったファイルの中身を GitHub の最新版に貼り替えて保存します。
  2. Api.gs を変えた場合は、「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン」を「新バージョン」にして、「デプロイ」を押します。
  3. ひな形にも同じ変更を反映します。
注意「新しいデプロイ」を選ぶと、ウェブアプリの URL が変わり、ポータルにつながらなくなります。更新は必ず「デプロイを管理」から行います。もし URL が変わってしまった場合は、clients.js の URL を新しいものに書き換えてください。

8. 年度を切り替える

  1. 入社後、旧年度のスプレッドシートの「内定者」シートで、全員の「利用」のチェックを外します。
  2. 新年度用に、ひな形から新しくスプレッドシートを作ります（「3. 新しい会社を追加する」と同じ手順）。
  3. 新しい会社コードを作って登録します。旧年度の URL は使えないままにしておきます。
  4. 旧年度の予定・お知らせ・コンテンツで使い回したいものは、新しいスプレッドシートにコピーします。

9. トラブル対応

症状原因と対応
「URLが正しくありません」と表示されるURL の c= の会社コードが clients.js に登録されていない。会社コードの登録と、「設定」シートの会社コードが一致しているかを確認する。
「このURLは使えません」と表示されるその内定者の「利用」が外れている、または個人キーが違う。「内定者」シートを確認し、必要なら再発行する。
「読み込みに失敗しました」と表示されるGAS の URL が変わった、またはデプロイの権限が外れた。「デプロイを管理」で URL とアクセス（全員）を確認する。
ロックを今すぐ解除したい「内定者」シートの非表示列（列見出しの間の矢印で再表示）にある「ロック解除日時」を消す。または再発行する。
画面がおかしい、エラーが出るスプレッドシートの「ログ」シートにエラーが記録される。内容を控えて Claude Code に相談する。
ID が重複した、消えた行を削除したりコピーしたりすると起きる。手で直さず、どの行で起きたかを控えて相談する。

10. 守ること

  • GitHub に内定者の情報を置かない。スプレッドシートを書き出したファイル（xlsx・csv）は、アップロードしないでください。
  • 会社コードに社名を使わない。コードと会社の対応は、社内の管理表で管理します。
  • スプレッドシートを「リンクを知っている全員」で共有しない。
  • ポータル用アカウントは2段階認証を有効にし、パスワードは社内のパスワード管理の仕組みで共有します。
  • 内定者の住所・電話番号・学校名などはポータルに載せない。
お客様向けの入力方法は「運用ガイド」を参照してください。
